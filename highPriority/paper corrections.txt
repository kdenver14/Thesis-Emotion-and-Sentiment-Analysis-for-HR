9. FLOWCHART DESCRIPTION (Page 20)
================================================================================

Replace the flowchart description with:

---

This flowchart illustrates the workflow of the multimodal sentiment and emotion
analysis system. The process begins when an authenticated user uploads a video
file through the web dashboard. The Next.js API route validates the file type
(MP4, MOV, or AVI) and session metadata, then forwards the video to the FastAPI
inference server. The inference server performs three parallel operations:
(1) speech-to-text transcription using OpenAI Whisper, (2) speaker diarization
using pyannote.audio to identify individual speakers, and (3) per-utterance
multimodal feature extraction using BERT (text), R3D-18 (video), and a Conv1D
CNN (audio mel-spectrograms). The extracted features are fused through
concatenation and passed to dual classification heads that predict emotion
(7 classes) and sentiment (3 classes) for each utterance. The results are
returned to the Next.js application, which computes aggregate statistics
(average emotions/sentiments, engagement score, emotional trajectory), persists
the analysis session and utterances to the SQLite database via Prisma, and
displays the results on the dashboard.

---

Brief descriptions:
  "The user wants to extract the emotions and sentiments of speakers in a
   recorded video interaction, view per-speaker breakdowns, and receive an
   engagement score and emotional trajectory summary."

Preconditions:
  • The system (Next.js app and FastAPI server) is running and accessible.
  • The multimodal model is loaded in the inference server.
  • The user is authenticated via NextAuth.js.

Post conditions:
  • Analysis results (utterances, emotions, sentiments) are persisted in
    the SQLite database.
  • Engagement score and summary are computed and stored.
  • Results are displayed on the dashboard for the user.

Main Flow:
  1. User logs into the dashboard with email and password.
  2. User navigates to the analysis page and uploads a video file.
  3. User fills in session metadata (title, type, employee, date).
  4. The system validates the file type and metadata.
  5. The system forwards the video to the FastAPI inference server.
  6. The inference server transcribes speech (Whisper), identifies speakers
     (pyannote), and extracts multimodal features per utterance.
  7. The model predicts emotion and sentiment for each utterance.
  8. Results are returned to Next.js, which computes averages, engagement
     score, and emotional trajectory.
  9. The session and utterances are saved to the database.
  10. The dashboard displays per-utterance results, speaker breakdown,
      aggregate emotions/sentiments, and the engagement score.

Alternative Flow:
  A1:
  1. User uploads an unsupported file type.
  2. System returns an error: "Unsupported file type."

  A2:
  1. The inference server is unavailable or fails.
  2. System returns: "Inference failed" (HTTP 502).
